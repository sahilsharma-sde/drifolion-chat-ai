# Nexus AI — Setup & Deployment

## What changed in this pass

**Auth & authorization**
- Email/password (JWT, bcrypt-hashed) + Google Sign-In, both issuing an access token (15m) and refresh token (7d).
- Every conversation, message, chat, and document route now requires a valid access token and is scoped to `req.user.id` — one user can no longer read or act on another user's data (previously there was no user model at all).
- Frontend auto-refreshes an expired access token once, transparently, before failing a request.

**Security/optimization**
- `helmet`, per-route + global rate limiting, dynamic CORS driven by `FRONTEND_URL` (was hardcoded to `localhost:5173`).
- Central error handler + `asyncHandler` so controllers no longer need repetitive try/catch.
- Server now fails fast at boot if required env vars are missing, instead of silently misbehaving.
- Fixed a case-sensitivity bug (`MessageBubble.css` vs `messageBubble.css`) that would have broken the production build on Linux hosts (Render/Vercel/etc. are case-sensitive; your local machine likely isn't).
- Code-split the syntax highlighter and routes: main JS bundle dropped from ~1.03 MB to ~237 KB (gzip: 351 KB → 76 KB). The logo asset dropped from 982 KB to 59 KB (was a 1254×1254 PNG displayed at ~36px).
- Added `.gitignore` to both apps — `.env` and `node_modules` were previously untracked-but-unignored.

**UI**
- Login/Register pages with a signature visual (an animated diagram of your actual supervisor → router → agents graph — not a generic illustration).
- Navbar with user avatar, name, and logout.
- Protected routing: unauthenticated users are redirected to `/login`.

## ⚠️ Before you push this anywhere public

Your uploaded `.env` had a **live Groq API key** in it. Rotate it now at https://console.groq.com/keys, then put the new key in `backend/.env`. The JWT secrets in your local `.env` were freshly generated by me and are not shown anywhere in this conversation — but you should still treat any secret that ever left your machine as compromised and rotate it before deploying.

## Local setup

**Backend**
```
cd backend
npm install
cp .env.example .env   # fill in GROQ_API_KEY, MONGODB_URI, JWT secrets, GOOGLE_CLIENT_ID
npm run dev
```

**Frontend**
```
cd frontend
npm install
cp .env.example .env   # fill in VITE_API_URL, VITE_GOOGLE_CLIENT_ID
npm run dev
```

Generate JWT secrets with:
```
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## Google OAuth setup

1. https://console.cloud.google.com/apis/credentials → Create Credentials → OAuth Client ID → Web application.
2. Authorized JavaScript origins: `http://localhost:5173` and your deployed frontend URL.
3. Copy the Client ID into `GOOGLE_CLIENT_ID` (backend) and `VITE_GOOGLE_CLIENT_ID` (frontend). No client secret is needed for this flow (ID-token verification, not the OAuth code exchange).

## Deploying (Render/Railway backend + Vercel frontend)

**Backend (Render/Railway)**
- Build command: `npm install && npm run build`
- Start command: `npm start`
- Env vars: `PORT` (usually auto-set), `MONGODB_URI` (use MongoDB Atlas free tier if you don't have a hosted Mongo), `GROQ_API_KEY`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `GOOGLE_CLIENT_ID`, `FRONTEND_URL` (your Vercel URL, e.g. `https://nexus-ai.vercel.app`).
- Health check path: `/api/health`.
- ChromaDB: this project talks to Chroma via `chromadb` client — you'll need a reachable Chroma instance (Chroma Cloud, or a small container on the same host) for RAG features; it's not spun up automatically by Render/Railway.

**Frontend (Vercel)**
- Root directory: `frontend`
- Build command: `npm run build`, output directory: `dist`
- `vercel.json` is already set up for SPA routing (so `/login` etc. don't 404 on refresh).
- Env vars: `VITE_API_URL` (your Render/Railway backend URL), `VITE_GOOGLE_CLIENT_ID`.
- Add the Vercel URL to Google's Authorized JavaScript origins once you have it.

## What's still worth doing next (didn't fit in this pass)

- **Refresh-token rotation/revocation**: currently a refresh token is valid until it expires; there's no server-side blocklist for "log out everywhere" or stolen-token revocation. Worth adding if you want to talk about it in interviews.
- **Per-document access control in Chroma**: uploaded PDFs go into a single shared vectorstore. Fine for a personal demo; if multiple people use this live, you'd want per-user namespacing so RAG answers don't leak across accounts.
- **Streaming markdown properly**: the assistant's streaming text renders as plain `<pre>`, then re-renders as Markdown only once the message is complete — a minor but noticeable flash.
- **Loading/error states for conversation list and chat load failures** — currently just `console.error`.
- **Tests** — there are none yet; even a handful of integration tests around auth + ownership checks would be a strong resume signal ("tested the authorization boundary").

## Troubleshooting

**Google: "Access blocked … no registered origin / Error 401: invalid_client"**
This comes from Google, not from the app. In Google Cloud Console → APIs & Services → Credentials, open the OAuth client and check:
1. Application type is **Web application** (not Desktop/Android).
2. **Authorized JavaScript origins** lists the exact address you open the app at: `http://localhost:5173` (and `http://localhost`). No trailing slash, and `127.0.0.1` counts as a different origin.
3. OAuth consent screen: if the app is in *Testing*, add your Google account under **Test users**.
4. The same client ID is in `frontend/.env` (`VITE_GOOGLE_CLIENT_ID`) and `backend/.env` (`GOOGLE_CLIENT_ID`). Restart `npm run dev` for the frontend after editing `.env`.
Changes can take a few minutes to apply. When you deploy, add the Vercel URL as another authorized origin.

**RAG answers say "no documents found" / retrieval is empty**
- Start ChromaDB: `cd backend && docker compose up -d` (set `CHROMA_URL` if it runs elsewhere).
- Documents are private to each account. Log in and attach a PDF with the paperclip button; PDFs indexed by older versions have no owner and won't be found, so upload them again.
- Scanned (image-only) PDFs have no text to index.

**Guest chat**
Not logged in = one anonymous chat per network (IP), `GUEST_MESSAGE_LIMIT` messages (default 10), expiring after `GUEST_TTL_HOURS` (default 24). Guests can't upload documents. Only a hash of the IP is stored.

## Free document Q&A on Render: use Qdrant Cloud instead of Chroma

You don't need to host ChromaDB. Qdrant Cloud has a free cluster (no credit card), and the app can use it as its vector store.

1. Sign up at cloud.qdrant.io and create a **Free** cluster. Choose a region close to your Render backend.
2. When it's ready, copy the cluster **URL** (it looks like `https://xxxx.region.cloud.qdrant.io:6333`, keep the `:6333`) and create an **API key** for it.
3. On the backend (Render), set:

```
VECTOR_STORE=qdrant
QDRANT_URL=https://xxxx.region.cloud.qdrant.io:6333
QDRANT_API_KEY=<your key>
```

On startup the server creates the `nexus_rag` collection and its filter indexes automatically (change the name with `QDRANT_COLLECTION`). Every search is filtered by user, so accounts only ever see their own documents. You can skip `CHROMA_URL` entirely.

Locally you can keep `VECTOR_STORE=chroma` (with `docker compose up -d`), or run Qdrant with `docker run -p 6333:6333 qdrant/qdrant` and set `VECTOR_STORE=qdrant`, `QDRANT_URL=http://localhost:6333` (no API key needed).

Free clusters are paused after a period of inactivity, so check Qdrant's current policy and open the cluster in the dashboard now and then, especially before showing the project to someone.
